services:
  mysql-julituradm:
    image: mysql:8.0
    container_name: mysql-julituradm
    restart: unless-stopped

    environment:
      MYSQL_DATABASE: ${MYSQL_DATABASE:?Defina MYSQL_DATABASE no .env}
      MYSQL_USER: ${MYSQL_USER:?Defina MYSQL_USER no .env}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD:?Defina MYSQL_PASSWORD no .env}
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:?Defina MYSQL_ROOT_PASSWORD no .env}

    ports:
      - "127.0.0.1:${MYSQL_PORT:-3309}:3306"

    volumes:
      - mysql_julituradm_data:/var/lib/mysql

    healthcheck:
      test:
        - CMD
        - mysqladmin
        - ping
        - -h
        - 127.0.0.1
        - -uroot
        - "-p$${MYSQL_ROOT_PASSWORD}"
      interval: 10s
      timeout: 5s
      retries: 10
      start_period: 30s

volumes:
  mysql_julituradm_data:
    name: mysql_julituradm_data



Por que essa configuração?
- 127.0.0.1:3309: restringe a publicação da porta à própria máquina, sem expor o MySQL diretamente à rede.
- mysql_julituradm: nome exclusivo do contêiner.
- mysql_julituradm_data: volume exclusivo para preservar os dados mesmo se o contêiner for recriado.
- healthcheck: permite verificar quando o MySQL estiver pronto.
- As senhas são lidas do .env, não escritas no compose.yaml.

Importante: o MySQL utiliza as variáveis de inicialização principalmente quando o diretório de dados está vazio.

Alterar senhas no .env posteriormente não altera automaticamente as senhas de um banco já inicializado.
