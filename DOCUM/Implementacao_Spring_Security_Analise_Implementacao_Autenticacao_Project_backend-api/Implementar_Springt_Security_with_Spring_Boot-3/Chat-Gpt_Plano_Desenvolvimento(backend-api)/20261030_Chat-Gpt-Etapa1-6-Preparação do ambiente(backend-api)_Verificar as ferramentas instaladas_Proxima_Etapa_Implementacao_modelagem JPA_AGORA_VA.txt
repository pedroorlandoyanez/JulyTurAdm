## 3. Convenções de Roles e Authorities

O documento estabelece uma distinção essencial.

Roles armazenadas na tabela `roles`:

```
ADMIN
RECURSOS_HUMANOS
CONTAS_PAGAR
COBRANCA
CONTABIL
RESERVAS
```

Permissions armazenadas na tabela `permissions`:

```
CONTAS_PAGAR:INSERT
CONTAS_PAGAR:SELECT
CONTAS_PAGAR:UPDATE
CONTAS_PAGAR:DELETE
```

Na integração com Spring Security:

| Origem     | Valor no banco        | Authority em tempo de execução |
| ---------- | --------------------- | ------------------------------ |
| Role       | `ADMIN`               | `ROLE_ADMIN`                   |
| Role       | `CONTAS_PAGAR`        | `ROLE_CONTAS_PAGAR`            |
| Permission | `CONTAS_PAGAR:UPDATE` | `CONTAS_PAGAR:UPDATE`          |

O prefixo `ROLE_` será acrescentado pelo código Java, sem alterar o conteúdo armazenado no banco.

Para verificar permissões granulares, o documento estabelece o uso de `hasAuthority`, por exemplo:

```
@PreAuthorize("hasAuthority('CONTAS_PAGAR:UPDATE')")
```

A aplicação deverá carregar as permissões de todos os perfis atribuídos ao usuário, não apenas do primeiro perfil.&#x20;

Fase 1 — Especificação técnica JPA

1. Decisões de mapeamento

| Item                        | Decisão                                          |
| --------------------------- | ------------------------------------------------ |
| Estratégia de identificação | `BIGINT AUTO_INCREMENT` nas entidades principais |
| Chaves das associações      | Chaves primárias compostas                       |
| Relacionamentos             | Entidades `UserRole` e `RolePermission`          |
| Carregamento                | `FetchType.LAZY`                                 |
| Exclusão em cascata         | Não utilizar `CascadeType.REMOVE`                |
| Exclusão de associações     | Não utilizar `orphanRemoval` nesta etapa         |
| Auditoria                   | Gerenciada pelo MySQL                            |
| Datas Java                  | `LocalDateTime`                                  |
| Nome das tabelas            | Preservar os nomes SQL existentes                |
| DDL do Hibernate            | `ddl-auto: none`                                 |

Por que não usar `@ManyToMany` diretamente?

Porque as duas tabelas associativas têm chaves compostas e representam relações importantes para a
segurança.

Com entidades explícitas, teremos controle sobre a criação e remoção de associações e poderemos 
acrescentar regras de negócio futuramente sem reformular o modelo.

2. Relacionamentos e cardinalidade

| Entidade     | Relacionamento   | Cardinalidade |
| ------------ | ---------------- | ------------- |
| `User`       | `UserRole`       | 1:N           |
| `Role`       | `UserRole`       | 1:N           |
| `Role`       | `RolePermission` | 1:N           |
| `Permission` | `RolePermission` | 1:N           |

Os relacionamentos `@ManyToOne` das classes intermediárias apontarão para as entidades principais.

As coleções inversas serão `@OneToMany(mappedBy = ...)`, sempre com carregamento `LAZY`.

## 3. Auditoria MySQL

Na entidade `User`, os campos:

- `created_at`: preenchido pelo `DEFAULT CURRENT_TIMESTAMP`.
- `updated_at`: preenchido e atualizado automaticamente pelo MySQL.

No JPA, usaremos:

```
@Column(
    name = "created_at",
    insertable = false,
    updatable = false
)
private LocalDateTime createdAt;

@Column(
    name = "updated_at",
    insertable = false,
    updatable = false
)
private LocalDateTime updatedAt;
```

Assim, o Hibernate não tentará controlar esses campos.

Após uma atualização, o objeto Java que já está em memória poderá precisar de `refresh()` para
refletir o novo valor de `updated_at`.

```
package com.julyturadm.domain.entity;

import jakarta.persistence.*;
import lombok.AccessLevel;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;

import java.time.LocalDateTime;
import java.util.ArrayList;
import java.util.List;

@Entity
@Table(name = "users")
@Getter
@Setter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 100)
    private String name;

    @Column(nullable = false, unique = true, length = 255)
    private String email;

    @Column(nullable = false, length = 255)
    private String password;

    @Column(nullable = false)
    private Boolean enabled = true;

    @Column(
        name = "created_at",
        insertable = false,
        updatable = false
    )
    private LocalDateTime createdAt;

    @Column(
        name = "updated_at",
        insertable = false,
        updatable = false
    )
    private LocalDateTime updatedAt;

    @OneToMany(
        mappedBy = "user",
        fetch = FetchType.LAZY
    )
    private List<UserRole> userRoles = new ArrayList<>();
}
```

Observações técnicas:

- `GenerationType.IDENTITY` corresponde ao `AUTO_INCREMENT` do MySQL.
- `enabled` começa como `true`.
- `createdAt` e `updatedAt` são controlados pelo banco.
- `userRoles` representa a associação entre usuário e perfil.
- Não há exclusão em cascata.

## Etapa 6. Criar UserRole

Arquivo: `domain/entity/UserRole.java`

```
package com.julyturadm.domain.entity;

import com.julyturadm.domain.entity.id.UserRoleId;
import jakarta.persistence.*;
import lombok.AccessLevel;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;

@Entity
@Table(name = "users_roles")
@Getter
@Setter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class UserRole {

    @EmbeddedId
    private UserRoleId id;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @MapsId("userId")
    @JoinColumn(
        name = "user_id",
        nullable = false,
        foreignKey = @ForeignKey(name = "FK_ur_user")
    )
    private User user;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @MapsId("roleId")
    @JoinColumn(
        name = "role_id",
        nullable = false,
        foreignKey = @ForeignKey(name = "FK_ur_role")
    )
    private Role role;
}
```

O `@MapsId` informa ao Hibernate que os campos `userId` e `roleId` da chave composta correspondem
aos identificadores das entidades relacionadas.
