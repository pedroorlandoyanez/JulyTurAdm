```
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;

public record UserCreateRequest(

    @NotBlank(message = "O nome é obrigatório.")
    @Size(max = 100, message = "O nome deve ter no máximo 100 caracteres.")
    String name,

    @NotBlank(message = "O e-mail é obrigatório.")
    @Email(message = "Informe um endereço de e-mail válido.")
    @Size(max = 255, message = "O e-mail deve ter no máximo 255 caracteres.")
    String email,

    @NotBlank(message = "A senha é obrigatória.")
    @Size(min = 8, max = 72,
          message = "A senha deve ter entre 8 e 72 caracteres.")
    String password

) {
}

```

2. Entendendo as validações

| Anotação                   | Finalidade                                        |
| -------------------------- | ------------------------------------------------- |
| `@NotBlank`                | Impede valores vazios ou contendo apenas espaços. |
| `@Email`                   | Verifica o formato do e-mail.                     |
| `@Size(max = 100)`         | Respeita o limite do campo `name` no MySQL.       |
| `@Size(max = 255)`         | Respeita o limite do campo `email`.               |
| `@Size(min = 8, max = 72)` | Define o tamanho permitido da senha.              |

O limite de 72 caracteres considera a utilização futura do BCrypt, que processa no máximo 72 bytes.

Para uma implementação mais rigorosa com caracteres UTF-8, validaremos também o tamanho em bytes
antes da codificação.

O `record` é adequado aqui porque representa um objeto de dados imutável, sem necessidade de
getters e setters tradicionais.
