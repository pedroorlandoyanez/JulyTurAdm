```
public UserResponse findUserById(Long id) {
    User user = userRepository.findById(id)
            .orElseThrow(() -> new ResourceNotFoundException(
                    "Usuário não encontrado com o ID: " + id
            ));

    return toResponse(user);
}

@Transactional(readOnly = true)
public UserResponse findUserByEmail(String email) {
    User user = userRepository.findByEmail(email)
            .orElseThrow(() -> new ResourceNotFoundException(
                    "Usuário não encontrado com o e-mail: " + email
            ));

    return toResponse(user);
}

@Transactional(readOnly = true)
public List<UserResponse> findAllActiveUsers() {
    return userRepository.findAllByEnabledTrue()
            .stream()
            .map(this::toResponse)
            .toList();
}
```

Esses métodos utilizam os métodos que já existem no `UserRepository`.

- `findUserById`: procura pelo identificador.
- `findUserByEmail`: procura pelo e-mail.
- `findAllActiveUsers`: retorna somente usuários com `enabled = true`.
- `@Transactional(readOnly = true)`: identifica operações de consulta.

Etapa 2 — Adicionar ativação e desativação

Logo depois dos métodos de consulta, adicione:

```
public UserResponse disableUser(Long id) {
    User user = userRepository.findById(id)
            .orElseThrow(() -> new ResourceNotFoundException(
                    "Usuário não encontrado com o ID: " + id
            ));

    user.setEnabled(false);

    User updatedUser = userRepository.save(user);

    return toResponse(updatedUser);
}

public UserResponse enableUser(Long id) {
    User user = userRepository.findById(id)
            .orElseThrow(() -> new ResourceNotFoundException(
                    "Usuário não encontrado com o ID: " + id
            ));

    user.setEnabled(true);

    User updatedUser = userRepository.save(user);

    return toResponse(updatedUser);
}
```

Regra importante: não utilizaremos `userRepository.delete()` ou `deleteById()`.
A desativação preserva o registro e seus relacionamentos no banco.

```
    @Test
    void shouldFindUserById() {

        assertNotNull(response);
        assertEquals(1L, response.id());

        verify(userRepository).findById(1L);

    @Test
```

Próxima etapa — Controller REST

Agora vamos conectar a camada de serviço à API HTTP, criando:

`src/main/java/com/julyturadm/user/UserController.java`

A ideia é disponibilizar estes endpoints:

| Método HTTP | Endpoint                   | Operação             |
| ----------- | -------------------------- | -------------------- |
| POST        | `/api/users`               | Cadastrar usuário    |
| GET         | `/api/users/{id}`          | Consultar por ID     |
| GET         | `/api/users/email/{email}` | Consultar por e-mail |
| GET         | `/api/users`               | Listar ativos        |
| PATCH       | `/api/users/{id}/disable`  | Desativar            |
| PATCH       | `/api/users/{id}/enable`   | Reativar             |

Também vamos utilizar `@Valid` para validar os dados recebidos e preparar o tratamento padronizado
das exceções HTTP.

Minha proposta: antes de implementar o controller, vamos criar o tratamento global de exceções
com `@RestControllerAdvice`.

Assim, erros como usuário inexistente, e-mail duplicado e dados inválidos terão respostas HTTP
apropriadas, sem expor detalhes internos da aplicação.

Vamos seguir nessa ordem: tratamento global de exceções e, depois, controller REST.
